# تدقيق التكامل بين Chat-Frontend وChat-Api

تاريخ التدقيق: 2026-11-12. تمت مراجعة مستودعي الواجهة والخادم، ووثيقة `Chat-Api-frontend-endpoints.md`، وملفات Laravel للمسارات والقنوات والأحداث والتحقق والصلاحيات. هذا التدقيق لا يعد تدقيقًا أمنيًا شاملًا ولا يثبت تشغيل الخدمة في بيئة إنتاج.

## خريطة الوظائف إلى المسارات

| وظيفة الواجهة | المسار الفعلي في Chat-Api | حالة الربط في الواجهة |
|---|---|---|
| بدء Google OAuth | `GET /api/auth/google/redirect` | رابط تنقل عادي. يعيد callback JSON؛ لا يوجد تسليم تلقائي للرمز إلى الواجهة.
| التحقق من الرمز/المستخدم الحالي | `GET /api/auth/me` | مستخدم للتحقق قبل حفظ الرمز في ذاكرة React.
| تسجيل الخروج وإبطال الرمز الحالي | `POST /api/auth/logout` | مربوط؛ تُمسح حالة الرمز محليًا أيضًا.
| المشاركون المتاحون لبدء محادثة | `GET /api/chat` | مربوط؛ القائمة محدودة بما يعيده الخادم (حتى 8 مشاركين لديهم رسالة)، وليست دليل مستخدمين شاملًا.
| المحادثات الخاصة | `GET /api/direct-conversations`، `POST /api/direct-conversations` | عرض وإنشاء/استرجاع محادثة باستخدام `user_id` من قائمة `/chat` فقط.
| سجل الرسائل الخاصة | `GET /api/direct-conversations/{conversation}/messages?page={page}` | مربوط مع تحميل الصفحات الأقدم (20 رسالة للصفحة).
| إرسال/حذف رسالة خاصة | `POST /api/direct-conversations/{conversation}/messages`، `DELETE /api/direct-messages/{message}` | مربوط. لا يدعم الخادم تعديل الرسائل الخاصة.
| حالة الكتابة الخاصة | `POST /api/direct-conversations/{conversation}/typing` | يرسل التطبيق حالتي الكتابة/التوقف عند التأليف، ويعرض الحدث الوارد عند وجود Reverb.
| قائمة الرسائل العامة والبحث/الترتيب/المدى/الصفحات | `GET /api/messages` | مربوط بمعاملات `search`, `sort`, `range`, `page`; الصفحة 10 رسائل.
| إنشاء/تعديل/حذف رسالة عامة | `POST /api/messages`، `PATCH /api/messages/{message}`، `DELETE /api/messages/{message}` | مربوط؛ واجهة التعديل والحذف تظهر لصاحب الرسالة فقط، ويظل الخادم صاحب القرار النهائي للصلاحية.
| التعليقات وEmoji | `GET/POST /api/messages/{message}/comments`، `POST /api/messages/{message}/emoji-comments`، `DELETE /api/comments/{comment}` | مربوط؛ Emoji مخزن كتعليق وفق عقد الخادم.
| إدارة المحظورين | `GET /api/users/blocked`، `POST /api/users/{user}/block`، `DELETE /api/users/{user}/block` | مربوط. تُخفى محليًا المحادثات والمشاركون الذين حظرهم المستخدم الحالي.
| البث اللحظي | `POST /broadcasting/auth` وقنوات Reverb الخاصة | عميل Laravel Echo اختياري حسب إعدادات البيئة؛ بعد أحداث الرسائل يعيد جلب البيانات من API. يوجد polling احتياطي كل 15 ثانية.

جميع طلبات API المحمية ترسل `Authorization: Bearer …` و`Accept: application/json`. الرمز محفوظ في حالة التطبيق بالذاكرة فقط، وليس في `localStorage` أو `sessionStorage`؛ لذلك يلزم التحقق/إدخال الرمز مجددًا بعد إعادة تحميل الصفحة.

## إعداد Reverb

تُستخدم أسماء القنوات المنطقية في `routes/channels.php`: `chat` و`direct-chat.{conversation_id}`. عند استخدام `Echo.private(...)` يضيف Laravel/Pusher بادئة القناة الخاصة على مستوى بروتوكول الاشتراك؛ لذلك لا تمرّر `private-` داخل اسم القناة المنطقي. تمرر مصادقة `/broadcasting/auth` ترويسة Bearer. الحدث يحمل معرّفات فقط، ولذلك يعيد العميل قراءة المسار المصرح به بدل عرض حمولة حدث على أنها محتوى موثوق.

للتفعيل، اضبط في بيئة الواجهة `VITE_REVERB_APP_KEY`, `VITE_REVERB_HOST`, `VITE_REVERB_PORT`, `VITE_REVERB_SCHEME`، واضبط `VITE_REVERB_AUTH_URL` عند الحاجة. مفتاح التطبيق الظاهر للمتصفح ليس سرًا؛ لا تضع `REVERB_APP_SECRET` أو أي سر Backend في متغيرات `VITE_*`. يجب أيضًا ضبط `REVERB_ALLOWED_ORIGINS` وCORS على الخادم إلى نطاقات النشر الفعلية. إن غابت بيانات Reverb، يستمر تحديث الواجهة عبر polling.

## فروق/مخاطر مؤكدة في الـ Backend

1. أسماء القنوات في ملف Endpoints ليست مطابقة تمامًا لأسماء القنوات المنطقية في Laravel. `routes/channels.php` يعرف `chat` و`direct-chat.{id}`، بينما الصيغ على سلك الاشتراك الخاص تظهر `private-chat` و`private-direct-chat.{id}`. تعتمد الواجهة أسماء Laravel المنطقية مع `Echo.private`.
2. `GET /api/direct-conversations` يضمّن آخر رسالة ولا يفلتر المحادثات عند وجود حظر، رغم أن قراءة الرسائل/إرسالها يتحققان من الحظر. الواجهة تخفي محليًا الطرف الذي حظره المستخدم الحالي، لكن لا يمكنها معالجة حظر بدأه الطرف الآخر ولا تعوض فحص الخادم.
3. تفويض قناة `direct-chat.{id}` يتحقق من أن المشترك أحد طرفي المحادثة ولا يتحقق من وجود حظر. قد يستمر الطرفان في تلقي أحداث القناة بعد الحظر. يلزم إصلاح ذلك في Backend؛ إخفاء الواجهة ليس حدًا أمنيًا.
4. الأحداث العامة تبث معرّفات، لكن مؤشر الكتابة العام يرسل اسم/معرّف المستخدم لمشتركي القناة؛ على الواجهة ألا تعتبر الحدث إذنًا لعرض بيانات محجوبة، وتستند إلى API المفلتر.
5. حذف الرسالة الخاصة يتحقق من الملكية، لكن ينبغي مراجعة هل يجب كذلك منع الحذف أو البث على محادثة محظورة. معالجة الواجهة لا تزيل الحاجة إلى سياسة خادم متسقة.
6. الحدث/القناة الفعلية وفحوص الحظر مستندة إلى الكود؛ ينبغي تحديث وثائق API واختبارات Backend عند إصلاح هذه الاختلافات.

## وظائف لا يقدمها العقد الحالي

لا توجد مسارات موثقة/موجودة لرفع الصور أو الملفات، أو تعديل الرسائل الخاصة، أو البحث الشامل عن المستخدمين/دليل جهات الاتصال، أو تعديل بيانات الملف الشخصي/الصورة، أو الإشعارات، أو إيصالات القراءة والتسليم، أو حالة الاتصال/آخر ظهور. لم تُنشأ أزرار تدّعي هذه الوظائف. يوجد مسار `/api/typing` للكتابة العامة في الخادم، لكن الواجهة الحالية لا ترسل إليه.

تدفق Google الحالي يعيد JSON من callback على نطاق API. لا توجد آلية Backend موثقة لإعادة توجيه المستخدم إلى الواجهة مع الرمز؛ لهذا تعرض الواجهة تعليمات النسخ/اللصق بدل اختراع نقل رمز في URL أو تخزينه الدائم.

## التشغيل المحلي

```bash
cd Chat-Frontend
npm ci
cp .env.example .env.local
# راجع VITE_API_BASE_URL وبيانات VITE_REVERB_* في .env.local
npm run dev
```

يعمل Vite افتراضيًا على `http://localhost:5173`. تأكد أن خادم Laravel يعمل على عنوان API المحدد، وأن `CORS_ALLOWED_ORIGINS` و`REVERB_ALLOWED_ORIGINS` في الخادم تسمحان بأصل الواجهة. لتجهيز نسخة الإنتاج استخدم `npm run build` ثم `npm run preview`. بعد OAuth، انسخ `access_token` من JSON الذي يعيده الخادم، والصقه في شاشة الواجهة؛ الرمز لا يبقى بعد تحديث الصفحة.

## الاختبارات والتحقق

- `npm test`: 6 اختبارات Vitest/React Testing Library ناجحة (اختبارات عميل API لأشكال الطلبات/الأخطاء، وفحص شاشة المصادقة).
- `npm run build`: ينجح فحص TypeScript الصارم وبناء Vite.
- `npm run lint`: ينتهي دون أخطاء؛ توجد تحذيرات React hooks في آثار تحميل البيانات.
- لم يمكن تشغيل PHPUnit أو اختبار التكامل الحقيقي مع Laravel/Reverb في بيئة التدقيق لغياب PHP وComposer واعتمادات `vendor`، ولم تُختبر اتصالات WebSocket ضد خادم حي.
- لم تُضف اختبارات Playwright حتى الآن؛ لا تعتبر اختبارات المتصفح/الأداء أو المراجعة الأمنية الإنتاجية مكتملة.
